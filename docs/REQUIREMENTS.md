# 생리 주기 관리 앱 개발지침서 (V1.0, 2026-11-22)

> 결정이 필요했던 해석은 `docs/ARCHITECTURE.md`의 "설계 결정" 절에 기록한다.

## 1. 프로젝트 개요
### 1.1 개발 목적
사용자가 실제 생리 시작일과 종료일을 간편하게 기록하고, 누적된 개인 데이터를 분석하여 향후 생리 예정일을 예측한다. 예측 결과는 Google Calendar, iOS 기본 캘린더, Android 기본 캘린더에 자동으로 동기화한다.
### 1.2 핵심 개발 원칙
- 최소 터치로 기록 및 수정
- 달력 중심의 미니멀한 UI
- 실제 기록과 예상 기록의 명확한 구분
- 누적된 전체 실제 주기 데이터 활용
- 불규칙한 주기의 예측 반영 여부를 사용자 직접 선택
- 스트레스 기록과 예측 반영 여부를 독립적으로 관리
- 과거 실제 기록 보존
- 외부 캘린더 중복 등록 방지
- 민감한 건강정보의 안전한 저장

## 3. 메인 화면 UI
### 3.1 기본 구성
앱 실행 시 월간 달력을 가장 먼저 표시한다. 기본 노출 요소:
1. 연도 및 월 표시
2. 이전 달 / 다음 달 이동
3. 월간 달력
4. 실제 생리 기간 표시
5. 예상 생리 기간 표시
6. 다음 예상 생리 시작일
7. 캘린더 설정 진입 버튼

불필요한 카드, 장식, 통계, 설명 문구는 최소화한다.
### 3.2 날짜 표시
- 실제 생리 기간: 분홍색
- 예상 생리 기간: 연한 분홍색
- 생리 시작일: 날짜 칸 전체를 분홍색으로 강조
- 시작일 삭제: 날짜 칸 왼쪽 상단 × 버튼
- 실제 기록과 예상 기록은 색상 및 표시 방식으로 구분

## 4. 생리 시작일 및 종료일 입력
### 4.1 날짜 선택
달력에서 날짜를 한 번 터치하면 작은 팝업 표시. 버튼은 **시작**, **종료** 두 개만.
### 4.2 시작일 입력
1. 날짜 선택 2. 시작 터치 3. 실제 생리 시작일로 저장 4. 날짜 칸 분홍색 표시 5. 주기 자동 재계산 6. 외부 캘린더 동기화 예약
### 4.3 종료일 입력
1. 날짜 선택 2. 종료 터치 3. 해당 생리 기록의 종료일 저장 4. 시작일~종료일 실제 기간 표시. 종료일은 선택 입력.
### 4.4 드래그 수정
기존 시작일/종료일을 길게 누르면 이동 모드.
- 길게 누르기 → 드래그 → 손가락 떼기
- 드래그 중 변경 위치 미리보기
- 드래그 종료 시 데이터 저장
- 드래그 중 외부 캘린더 동기화 금지
- 날짜 변경 후 되돌리기 지원
- 시작일과 종료일 순서가 잘못되는 경우 충돌 처리
### 4.5 삭제
- 시작일 및 종료일에 × 표시, × 터치 시 해당 기록 삭제
- 삭제 직후 되돌리기 제공
- 삭제 후 관련 통계 및 미래 예측 재계산

## 5. 생리 주기 데이터 구조
### 5.1 주기 계산 원칙
연속된 실제 생리 시작일 사이의 날짜 차이로 계산한다. (예: 5/4→6/1 = 28일, 6/1→6/30 = 29일). 한 달에 시작일이 두 번 있을 수 있으므로 월 단위가 아닌 개별 생리 기록 단위로 관리한다.
### 5.2 주기 연결 원칙
선택한 생리 시작일은 해당 주기의 종료 기준점이다. 6/1 선택 시 해당 주기 5/4→6/1(28일), 6/30 선택 시 6/1→6/30(29일). 주기별 설정은 선택한 실제 생리 시작일 기록에 연결한다.

## 6. 주기 상세 설정 UI
실제 생리 시작일을 선택하면 해당 주기 상세 설정을 표시한다.
### 6.1 구성
```
해당 주기
6월 1일 → 6월 30일
29일
예측에 반영: ON/OFF 토글
스트레스: 😊 / 😐 / 😣
```
두 기능은 독립적으로 설정한다.
### 6.2 예측에 반영
- 기본값 ON
- OFF 시 해당 주기 간격만 예측 계산에서 제외
- 실제 생리 기록은 삭제하지 않음
- 다른 주기의 설정에 영향 없음
- 설정 변경 시 미래 예상 일정 재계산
- 직전 실제 시작일이 없어 주기를 계산할 수 없으면 토글 비활성화
### 6.3 스트레스 기록
점수화하지 않는다. 😊 편안함 / 😐 보통 / 😣 스트레스 많음. 한 번 터치하면 즉시 선택 및 저장. 기본 선택 강제하지 않으며 미기록은 내부적으로 "미입력"으로 관리.
### 6.4 스트레스와 예측 반영의 독립성
- 스트레스 변경 시 예측 반영 토글 자동 변경 금지
- 예측 반영 OFF 시 스트레스 상태 자동 변경 금지
- 두 설정을 별도 필드로 저장
- 스트레스 데이터는 향후 개인화 분석에 활용
- 초기 버전에서는 스트레스만으로 예상일을 직접 보정하지 않는다

## 7. 생리 주기 예측 알고리즘
### 7.1 기본 원칙
모든 실제 기록을 보존하고, 예측에 포함하도록 선택한 유효 주기 전체를 사용한다.
- 예측 주기 = 예측에 반영 ON인 실제 주기 간격들의 평균
- 다음 예상 시작일 = 가장 최근 실제 시작일 + 예측 주기
- OFF인 간격은 평균에서 제외하되 실제 시작일 기록은 유지
### 7.2 실제 시작일 기준 재설정
예상 6/5, 실제 6/17, 예측 주기 28일 → 다음 예상 7/15. 기존 예상일을 기준으로 쓰지 않는다.
### 7.3 과거 기록 수정
6월 실제 시작일 6/17→6/19 수정, 7/18 유지 시:
1. 수정한 6월 기록만 변경 2. 다른 실제 시작일 불변 3. 5–6월, 6–7월 간격 재계산 4. 전체 유효 주기 통계 재계산 5. 미래 예상 시작일 재계산 6. 변경된 예상 일정만 외부 캘린더에 반영
### 7.4 추가 예외 처리
- 과거 실제 기록은 사용자가 직접 수정할 수 있다
- 다른 실제 기록은 자동 수정하지 않는다
- 예측값을 실제 기록처럼 학습 데이터에 사용하지 않는다
- 주기 제외 시 양옆 기록을 합쳐 새로운 주기를 만들지 않는다
- 과거 기록 수정으로 주기 연결이 달라지면 해당 설정의 유효성을 확인한다
- 유효 주기가 부족하면 사용자 설정 기본 주기를 활용한다
- 예측 결과는 확정일이 아닌 예상일로 표시한다
### 7.5 개인화 예측 고도화
초기 버전은 전체 유효 주기 평균. 추후 검토: 최근 주기 변화 경향, 변동 폭, 예측 오차 분석, 스트레스와 주기 변화 상관관계, 개인 패턴 기반 예상 범위. 단순 평균을 빅데이터 기반 고정밀 모델이라고 표현하지 않는다. 외부 데이터 모델은 출처·적합성·검증이 확보된 후 도입.

## 8. 생리 기간 예측
- 유효한 과거 생리 기간 평균 활용, 부족하면 사용자 설정 기본 기간
- 예상 시작일~예상 종료일 달력 표시
- 실제 종료일 입력 시 해당 주기 예상 기간을 실제 기록으로 대체
- 시작일만 입력된 상태는 "실제 종료일 미확정"으로 저장
- 실제 기간과 예상 기간을 혼동하지 않도록 구분

## 9. 외부 캘린더 동기화
### 9.1 지원 대상
iOS: Google Calendar 토글, iOS 캘린더 토글 / Android: Google Calendar 토글, Android 캘린더 토글. 두 토글은 독립적이며 동시 활성화 허용.
### 9.2 연동 방식
- Google: OAuth 인증, Calendar API로 일정 생성·수정·삭제
- iOS: EventKit, 캘린더 쓰기 권한 요청
- Android: Calendar Provider, 필요한 캘린더 권한 요청
- 동일한 실제 Google 캘린더가 API 및 기기 캘린더 경로로 동시에 선택되면 중복 등록 방지
### 9.3 동기화 범위
기본적으로 향후 3개월 예상 일정만 등록. 실제 기록과 미래 예측은 별도 관리. 실제 기록은 과거 기록이더라도 사용자가 선택한 동기화 정책에 따라 보존 및 갱신.
### 9.4 동기화 최적화
- 드래그 중 동기화 금지
- 마지막 수정 후 3초간 추가 변경이 없으면 동기화 시작, 3초 이내 추가 수정 시 이전 예약 취소
- 최종 상태만 동기화
- 기존 일정과 새 예측 비교: 불변 일정 유지, 변경분만 수정, 불필요한 예상 일정만 삭제, 새 일정만 생성
- 3초 대기 중 앱 종료 시 다음 실행에서 미동기화 상태 재처리
### 9.5 동기화 안정성
- 앱이 만든 일정의 고유 ID 관리, 실제/예상 일정 구분
- 동기화 대상별 상태 개별 저장
- 진행 중 중복 실행 방지
- 네트워크 오류 시 로컬 기록 보존, 실패 시 재시도, 재시도 중 중복 생성 방지
- 권한 해제 및 대상 캘린더 삭제 예외 처리
- 동기화 성공 후에만 성공 상태 표시
### 9.6 자동 갱신 시점
1. 시작/종료일 입력 2. 기존 기록 수정·삭제 3. 예측 반영 토글 변경 4. 앱 실행/재진입 5. 수동 동기화.
장기간 미실행 시 3개월 범위 자동 연장은 OS 백그라운드 제한을 고려해 별도 설계. Google Calendar 새로고침만으로 앱 내부 예측이 재계산된다고 가정하지 않는다.

## 10. 개인정보 보호
생리 기록과 스트레스 정보는 민감한 건강정보.
- 기기 내부 저장 기본, 전송 구간 암호화, Google 인증 토큰 안전 보관
- 최소 캘린더 권한, 불필요한 외부 서버 전송 금지, 분석·광고 SDK로 건강정보 전달 금지
- 앱 기록 전체 삭제 기능, 외부 캘린더 연동 해제 기능, 앱이 생성한 일정만 식별·관리
- 연동 전 건강정보가 외부 캘린더 서비스에 저장될 수 있음을 명확히 안내
- 타인의 건강정보 입력은 당사자 동의 전제

## 11. UI 디자인 지침
### 11.1 스타일
미니멀한 iOS 스타일 기본, Android에서도 자연스럽게 반응형. 흰색/연한 중립색 배경, 분홍색은 생리 기록 구분에 집중. 과도한 그림자·그라데이션·카드·장식 배제. 날짜 칸 균일한 크기. 필수 조작만 기본 화면에.
### 11.2 조작 원칙
날짜 터치 → 시작/종료 · 길게 누르기 → 드래그 수정 · × → 삭제 · 예측 반영 → ON/OFF · 스트레스 → 이모지 한 번 터치 · 선택 즉시 자동 저장. 불필요한 확인 팝업 및 저장 버튼 없음.
### 11.3 주기 설정 표시
예측 반영 토글과 스트레스 이모지는 달력 상단에 고정하지 않고, 실제 시작일을 선택했을 때 해당 주기 설정으로 표시. 한 달에 여러 시작일이 있어도 주기별로 독립 관리.

## 12. 데이터 모델 (최소)
- **PeriodRecord**: ID, 실제 시작일, 실제 종료일(선택), 생성 시각, 수정 시각
- **CycleRecord**: ID, 직전 생리 시작 기록 ID, 해당 생리 시작 기록 ID, 주기 길이, 예측 반영 여부, 스트레스(미기록/편안함/보통/많음)
- **Prediction**: ID, 예상 시작일, 예상 종료일, 계산에 사용한 데이터 버전, 예측 생성 시각
- **CalendarSync**: 연동 대상, 실제 캘린더 ID, 앱 내부 기록 ID, 외부 일정 ID, 일정 유형(실제/예상), 마지막 동기화 상태, 마지막 동기화 시각

주기 데이터는 날짜 문자열이 아닌 기록 ID 중심으로 연결. 날짜 수정·삭제로 관계가 바뀌면 연결을 재계산하고 설정값이 잘못된 주기에 적용되지 않게 처리.

## 13. 테스트 필수 항목
